# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A radio jukebox for an old Android phone running Termux. MPD plays the radio streams, a single-file Flask app ([radio_web.py](radio_web.py)) is the web remote, and a Cloudflare quick tunnel exposes that remote publicly. Development happens on Windows, but everything runs only on the phone under Termux. There is no build step, test suite or linter.

## Runtime architecture

- **MPD** listens on `127.0.0.1:6600` only (the app and `mpc` connect to localhost; open to the LAN, anyone on the same Wi-Fi had the full MPD protocol, `kill` included) and outputs audio through Android OpenSLES (`type "sles"`, software mixer, see [mpd.conf](mpd.conf)). Its paths use Termux conventions: playlists in `~/.config/mpd/playlists`, music in `~/storage/shared/Music`. Queue and state survive restarts through `state_file`.
- **radio_web.py** is stateless. Every route opens a fresh `MPDClient` connection to `localhost:6600`, runs one or two MPD commands, disconnects, then redirects (POST-redirect-GET).
- **Templates and pages** ([templates/](templates/)): `base.html` (head: the Manrope `@font-face` with `asset_url()` URLs, so they match the preload, plus [static/style.css](static/style.css) and [static/app.js](static/app.js); `asset_url()` adds a `?v=` hash so static files can be cached for a year, `SEND_FILE_MAX_AGE_DEFAULT`) → `layout.html` (the shell: `.nav`, `.main`, the player and the small modals `#nova` and `#config`) → one template per page, all rendered by `render_page(template, page, ...)` with the same context: `home.html` (`/`, Início: the dashboard), `discover.html` (`/descobrir`, `/descobrir/temas`, `/descobrir/paises`, `/search` and `/tema`, picked by `tab`), `playlists.html` (`/playlists`) and `playlist.html` (`/playlist?nome=`, any playlist in cards, including the one playing). `error.html` extends `base.html` only. Shared pieces are macros in `macros.html`, imported in each page `with context` (Jinja doesn't pass a parent's imports or top-level `set`s into child blocks, so `set`s live inside `{% block content %}`).
  - **Look:** dark, Spotify/TuneIn-like; colours are CSS variables on `:root`. Below 900px `.nav` is a bottom tab bar (Início · Descobrir · Playlists) and the player is a compact card above it; from 900px `.nav` is a left sidebar with the playlists (`nav-library`, covers from `station_index()`'s third value, the first four logos of each `.m3u`) and the player is a full-width bar. Everything respects `env(safe-area-inset-bottom)` (`viewport-fit=cover`), because Chrome on Android draws edge-to-edge.
  - **Icons:** Phosphor (MIT), only the ones used, as `<symbol>`s in [static/icons.svg](static/icons.svg); the `icon(name, cls)` template global writes `<svg class="i"><use href="/static/icons.svg?v=…#name">` (the URL is computed once per request in `g`). To add one, copy the SVG from `@phosphor-icons/core@2.1.1/assets/` into a new `<symbol>` (instructions in the file). No emojis as icons; country flags stay emoji, as content.
  - **Font:** Manrope (OFL, `static/fonts/`, latin and latin-ext woff2, licence in `OFL.txt`). Country flags use "Twemoji Country Flags" (`static/fonts/twemoji-flags.woff2`, from `country-flag-emoji-polyfill@0.1.10`, licence in `TWEMOJI-FLAGS-LICENSE.md`), declared in `base.html` with a `unicode-range` that only covers flag characters and listed first in `body`'s `font-family`: Windows has no flag emoji and would show the letters ("PT").
  - **Player** ([templates/player.html](templates/player.html)): a `<footer class="player">` that also contains the `#tocar` sheet (big logo, details, site and vote, big controls, volume, "Mostrar na lista" → `/#e<tile_id>`). `/estado` renders this whole file and the script swaps it, then calls `syncModals()` so an open `#tocar` stays open. `/previous` and `/next` wrap around the queue and skip the station being tried (they step over `listed()` song ids). The player has no `transform`/`filter`/`backdrop-filter`, which would trap the sheet's `position: fixed`.
  - **Modals only for small things:** `#nova`, `#config`, `#apagar-N`/`#apagar`, `#renomear` and `#tocar`. Searching, themes, countries and playlists are pages.
- **Descobrir** pages: the tabs (Nome, Temas, Países) are links to `/descobrir`, `/descobrir/temas`, `/descobrir/paises`, keeping `para`. Themes are coloured cards (`.genre.g0`–`g7`), countries flag cards; a chip submits `/tema`. The theme results (`tab == "tema"`) have a back button, a "+ Juntar N" button in the header that opens the `#juntar-todas` modal (in `{% block modals %}`, with the `/add_theme` form), the `.refine` filters and the rows. Below 900px `.refine` has no panel background and its filters are one horizontally scrolling row, so the stations start near the top. Results in search and themes use one `result_row()` macro: ▶ (`/ouvir`) and + (`station_buttons()`): a `<details class="add-menu">` whose list is one `/add_stream` form with a submit button per playlist (`name="para"`, empty for the queue), from `add_targets` (built in `render_page`: the `para` playlist first, then the playing one, each with its `urls`; the per-playlist URL sets come from `playlist_members()`, cached with `station_index()`). Playlists that already have the stream show ✓ instead of a button, and the + itself shows ✓ (`saved_urls`) when the stream is in any of them. The menu ends with a "Nova playlist" field (`nova_playlist`, `required`) and a `criar` button: `/add_stream` creates that playlist with the station through `append_to_playlist()`, without making it active (the music doesn't change); an existing name just gets the station. The field comes first in the HTML (CSS `order` moves it to the end) so Enter in it submits `criar`, the form's default button, and the playlist buttons carry `formnovalidate`. `saveFocus()` skips fields inside `.add-menu`, so the typed name isn't restored into another row's menu after the page swap. The script keeps one menu open, closes it on an outside click or Esc, and adds `.up` when the list would fall behind the player. There is no "Juntar a" select and no hint line any more. The `#juntar-todas` select defaults to `para` (else the active one); a new playlist is an explicit option labelled "(passa para o Início)", because a new target replaces the queue. The stream-URL form sits in a closed `<details>`, with a "Juntar a" select built from `add_targets` (so `para` comes first) and `next` set to the current page, so it stays on Descobrir and shows the notice. Filters are remembered in `localStorage` (`vee-radio-filtros`, per browser) and restored only on the three landing pages, for selects whose name is not in the URL. `para` (set by "Juntar rádios" on a playlist page) is only carried along: a hidden field in `filter_fields()` and the tab links.
- **Trying a station** (`/ouvir`, POST): MPD only plays what is in the queue, so the station is `addid`-ed at the end and recorded in `~/.config/vee-radio/a-ouvir.json` (`read_preview()`/`set_preview()`; a file, not memory, so an app restart can't let the next sync save it). `listed()` hides it from the tiles and `queue_sig()`, `queue_entries()` leaves it out of the `.m3u`, and the player shows "A experimentar" plus a "+ Juntar" form (`/add_stream`, which promotes it instead of adding it again; so does `/add_theme` into the active playlist). `drop_preview()` deletes it from the queue when another station is played (`/play_id`, `/previous`, `/next`, another `/ouvir`); routes that `clear` the queue just forget it, and start.sh deletes the file when the queue comes back empty. A URL already in the queue is just played.
- **Início** (`index()` → `home.html`, wrapped in `#painel`): a dashboard, not a list. "A tocar agora" (the player context: station, ICY title, preview/paused state; the card opens `#tocar`; links to `list_href`, the page of the list that is playing), the playlists as a `.shelf` of `.pl-card`s, "Ouvidas recentemente" and two highlight shelves of the saved stations ("As mais ouvidas" by `clickcount`, "Em alta" by positive `clicktrend`, `HIGHLIGHTS` each). Small cards use the `station_card` macro, which posts to `/ouvir` (plays it when it is already in the queue, else tries it). Highlights read only the cached `stats.json`; `index()` starts `refresh_stats_later()` (one background `station_stats()` run at a time, deduplicated as `"*"` in `_refreshing`) for saved stations whose numbers are missing or stale, so they appear on a later visit. The script reloads the dashboard softly when `#painel`'s `data-now` differs from the playing `id`. A stream error shows as a short notice linking to `list_href#aviso`.
  - **History** (`~/.config/vee-radio/historico.json`, `read_history()`/`note_played()`): `player_context()` records the playing station once it has played `HISTORY_MIN_SECONDS` (so skipping with ⏭ doesn't fill it), newest first, no repeats, `HISTORY_SIZE` entries with name and logo. `_history_last` avoids touching the file on every `/estado`.
- **Playlist page** (`view_playlist()` → `playlist.html`): every playlist in cards (`station_tile` macro), with the same filter and sort. `view.live` is true for the active playlist: cards come from the MPD queue (`listed()`), carry the song id and play/remove by id (`/play_id`, `/remove`), and the page has `#estacoes`, the error warning and the undo bar. Other playlists come from the `.m3u` file: a card posts to `/tocar_em` (`play_in()`: `switch_queue()` to that playlist, then play that station, unless it is already playing; Spotify-like, so ⏮ ⏭ then follow it) and its ✕ to `/playlist_edit` (`acao=remover`). `/playlist` without `nome` redirects to the active playlist, or shows the unsaved queue ("Lista por guardar", with "Guardar como playlist"). `queue_url()` is that page's URL; the player's "Mostrar na lista" links to it (`list_href`). Routes that make a playlist active (`/load_playlist`, `/create_playlist`, `/add_theme`) redirect to its page.
- **Station list filter and sort** (GET `/playlist?nome=...&filtro=...&ordenar=clickcount|votes|name|-name`): `station_cards()` sorts the tiles and renders the ones that don't match with `hidden`, so the script can filter while typing without a request. `plain_text()` (server) and `plain()` (script) must normalise the same way (NFKD, drop `\p{M}`, lowercase), or the page and live filter show different stations. This only changes the view: the saved playlist and previous/next keep the playlist order. Tiles carry the MPD song id (`data-id`), and `/estado` sends the playing `id`, which the script uses to move `.current`. The order dropdown reuses the `order_select` macro of the radio-browser filters, with `LIST_ORDERS`. While an order or filter is set, a note (`#nota-ordem`, toggled by the script while typing) says ⏮ ⏭ still follow the playlist order, hidden stations included; making them follow the view would need `station_stats()`, which may hit the API, on every press.
- **Station popularity and details** (`station_stats()`): sorting by clickcount (clicks in the last 24h), votes or clicktrend (change in clicks from the previous day), and the footer details, need radio-browser data for stations already in the queue. It is cached in `~/.cache/vee-radio/stats.json` for a day. Each entry maps a stream URL to `uuid`, `clickcount`, `votes`, `clicktrend`, `countrycode`, `tags` (up to 3), `homepage`, `codec`, `bitrate`, `voted_at` and `t`. `load_stats()` returns a shared copy that is only reparsed when the file changes (`file_sig()`), so callers must not mutate it; `merge_stats()` reads the file itself (`read_stats_file()`) and drops, through `prune_stats()`, entries for URLs in no playlist whose `t` and `voted_at` are older than a month. Bump `STATS_VERSION` when fields are added, so older entries count as stale. All writes go through `merge_stats()`, which rereads the file under `STATS_LOCK` and keeps `voted_at`.
  - **Known `uuid`:** stations with a known `uuid` are refreshed in one `byuuid` request (100 per call). Search and theme forms post `uuid` next to `url`, and `remember_uuids()` stores it when a station is added.
  - **Unknown `uuid`:** the rest are looked up with `byurl`, 8 in parallel, keeping the most clicked duplicate.
  - **Network failure:** a failed lookup keeps the old numbers and retries after an hour. After the first network error (`api_down`) the remaining lookups are skipped, so sorting a big list with the API down doesn't wait for every timeout.
- **Footer details** (`station_details()`): the player shows the flag, a detail line (MPD's live `bitrate`, falling back to the API's, plus the tags), a site link and a vote button.
  - **Never blocks:** `/estado` is polled every 5s, so `station_details()` only reads the cache. When the entry is missing or stale, it starts a background thread (deduplicated through `_refreshing`), and the player fills in on a later poll because its `data-sig` includes the details.
  - **Votes:** `/vote` (POST) votes for the playing station through `/json/vote/<uuid>`. radio-browser allows one vote per IP per station every 10 minutes (`VOTE_COOLDOWN`), and all viewers share the phone's IP. The route returns `estado(notice)`, and the script shows `notice` as a toast (green when `ok`). Tile forms carry a `next` field and their routes return via `back()`, so playing or removing a station keeps the filter. Their `next` is `list_url` (the playlist page plus only `filtro` and `ordenar`), never `/search` or `/tema`, which would query the API again. The script rebuilds `next` the same way (`listUrl()`) before sending, because the live filter only changes the URL. Most features follow the same pattern: a POST route plus a `<form>` in a page. Small dialogs are CSS-only modals opened with `:target` (a link to `#nova` shows `<div class="modal" id="nova">`, a link to `#fechar` hides it), so a redirect to `/...#nova` reopens a modal after a POST; anything list-like is a page.
- **Stream watchdog** (`watch_stream()`, a daemon thread started in `__main__`, with its own plain `MPDClient` connection, one `watch_step()` per second under `QUEUE_LOCK`): when a stream drops mid-play MPD sets no error, it silently plays the next queue entry (or stops if it was the last); when a stream fails to connect and there are more entries, it also skips. So the routes' connections are `RadioClient`, which records every `playid`/`play`/`stop` as the user's choice (`note_choice()`, `_choice` with a `seq`), even when MPD answers with an error; the watchdog compares MPD's state with that choice. Anything else (stopped, or another song) is a drop: it stops whatever MPD moved to and retries the chosen song id after each of `RETRY_DELAYS` (5 attempts, ~35 s). It only counts as recovered after `STABLE_SECONDS` of play, since a stream that connects and drops again is a failed attempt. Out of attempts, it switches to an untried version (`untried_version()`, `_fallback` remembers tried URLs per station for `FALLBACK_SECONDS`; notice "Não tocou nessa versão…" for `VERSION_NOTICE_SECONDS`); without one it stops and records the failure. `_watch` holds what the player shows (`{"url", "id", "attempt"}` while retrying, `{"url", "id", "failed", "name", "text"}` after failing): `player_context()` puts it in `stream_note` (in place of the ICY title, red when `stream_failed`, part of the sig), and `watched_song()` makes that song the current one for the player, ▶ (`/play` retries it) and ⏮ ⏭, because MPD's cursor may be on the next entry. `/estado` sends the failure text as `failed` (the script toasts it once when it changes) and in `error`. A removed song or a choice outside the app while nothing is chosen (`mpc play`) is adopted; `mpc stop` or `mpc next` are not recorded, so they look like drops and are retried.
- **Stream error warning** (`#aviso`, when `stream_error` is set: the watchdog's failure text, else MPD's `status.error`): `render_page` finds the failed tile by the watchdog's URL or by its URL inside the error text (`failed`; `failed_name` also covers a station being tried) and offers "Tocar a seguinte" (`/next`, which also clears the error because playback starts), "Procurar outra vez" (`/search?q=<name>#juntar`) and "Remover"; `/remove` calls `clearerror()` when the removed station is the one in the error. Without a match only "Tocar a seguinte" is shown. `STREAM_FAILED_HINT` is now only used by the MPD error page.
- **Responses** are gzipped in the `compress` after_request hook (HTML, JSON, SVG; over 1 KB; when the browser accepts it). A page with 500 stations goes from ~450 KB to ~25 KB, which matters on the LAN and between the phone and Cloudflare. `/add_theme` adds stations in one MPD command list (`command_list_ok_begin`) instead of one round trip each. Tiles carry `data-plain`, the name already normalised by `plain_text()`, so the live filter doesn't normalise every name on every key.
- **JavaScript** ([static/app.js](static/app.js)): the server does the work and is the source of truth (state, validation, rendering); the script stays thin and holds no rules of its own. New features may depend on the script when that gives a better experience (dragging, menus, richer confirmations); there is no requirement to work with JavaScript off. What exists today still works without it (plain forms, links and `:target` modals that the script enhances), and there is no reason to rewrite that. It sends every form with `fetch` and the `X-Requested-With: fetch` header:
  - For those requests an `after_request` hook turns redirects into `204` with an `X-Location` header, because `fetch` follows redirects itself and drops the `#modal` fragment. A route can add a short message with `with_notice(response, text)` (`X-Notice`, URL-encoded because headers are ASCII; the hook carries it over), which the script shows as a green toast after loading the new page: `/add_stream` ("«X» juntada a «Rock».", or "já estava em") and `/add_theme` (`joined_text()`, or "Playlist «X» criada com N rádios."). The script then GETs that location and swaps `document.body`: on the same path it keeps the page and open-modal scroll, on another path it starts at the top and reveals the `#fragment` element (`revealHash()`, which also flashes a tile).
  - **Links** to other pages of the app are loaded the same way (no full reload, history with `pushState`, `popstate` reloads); links that only change the `#`, external links, `target`, `/logo`, `/static` and `/entrar` are left to the browser.
  - The player routes (`play_id`, `ouvir`, `play`, `stop`, `previous`, `next`, `volup`, `voldown`) return `done()`, which gives the script the `/estado` JSON instead of a redirect.
  - Modals also open with a `.open` class kept in sync with `location.hash`, because `:target` does not follow `pushState` or swapped elements.
  - **Skeletons:** a `js` class on `<html>` (set inline in `base.html`) makes logos and thumbnails shimmer until their `load`/`error` event adds `.loaded`. The search form and `.refine` replace the page's `.results` with skeleton rows, and the list tools add `.is-loading` to `.stations`. A theme or country chip replaces `.main` with a heading (the chip's label) and skeleton rows, because the theme page does not exist yet. If the request fails, all of this is undone.
  - **Live search:** typing in the search box submits after 700ms (3+ characters). Changing a filter submits the search (when it has text) or the theme `.refine` form, whose button is then hidden. `loadSeq` drops responses older than the latest page request, and the focused text field (value and caret) survives the body swap.
  - Every 5s the script polls `/estado?sig=<data-sig>`. The sig is computed in Python (`with_sig()`), and when it matches the server sends `player: null` instead of rendering the player again. The script replaces the player when a new one arrives (keeping already-loaded logos from shimmering again), only toggles `.current` on the old and new tile, moves the `.current` tile and sets the tab title. `stateSeq` drops a poll response that was requested before a form was sent, so an old state can't undo a button press in the player. Only on the page of the playlist that is playing (`#estacoes` present): when the queue signature (`queue_sig()`, a hash of the MPD song ids, on `#estacoes` as `data-queue`) or the error state differs from the page, it reloads the page softly, but never while a modal is open or while selecting. MPD's own queue version (`status.playlist`) is not used, because it also changes when the playing stream's ICY tags change, which reloaded the page on every song.
- **Active playlist**: the MPD queue is always the playlist named in `~/.config/mpd/playlist-ativa.txt`. `/add_stream` and `/remove` call `sync_active()`, which rewrites that `.m3u` from the queue, so there is no save button. Every route that reads the queue and rewrites `.m3u` files holds `QUEUE_LOCK`, and `write_m3u` writes a `.tmp` and swaps it in with `os.replace`, so concurrent viewers never see or save a half-written playlist. Tiles play and remove by MPD song `id` (`/play_id/<id>`, `/remove/<id>` with `deleteid`), never by position, because the queue may have changed on another device since the page was rendered. Switching playlists never cuts the music: `/load_playlist`, `/create_playlist` (empty) and `/add_theme` (new target) go through `switch_queue()`, which deletes every queue entry except the playing (or paused) one and `load`s the new playlist after it. If that URL is in the new playlist, the loaded copy is deleted and the playing entry moved into its place (same song id, so MPD doesn't restart it); otherwise it stays at the end as the station being tried (preview, name and logo from `station_info()`), with "+ Juntar", until another station is played. Only when nothing is playing does `/load_playlist` (and `/add_theme` with stations) start the first one. `switch_queue()` clears the active file before touching the queue and sets it again afterwards, so a failed `load` can't make the next sync overwrite the previous playlist with what was left in the queue. URLs and playlist names with control characters are rejected (`safe_url`, `playlist_path`), because python-mpd2 doesn't escape newlines and they would inject MPD commands. Loading or creating a playlist makes it active, and deleting the active one clears the file, which leaves the queue unsaved. There is deliberately no "clear queue" action, because with sync it would wipe the playlist.
  - **Undo removal:** `/remove` records the station in `~/.config/vee-radio/removida.json` (`url`, `name`, `logo`, `pos` in `listed()` order, `playlist`, `t`), with the name and logo read before the sync drops them. For `UNDO_SECONDS` (2 min), and only while the same playlist is active (`read_removed()`), the page shows an "Anular" bar (`.undo`, `data-left` seconds for the script to hide it); `/anular` re-adds it with `addid(url, pos)` and passes the name and logo to `sync_active(c, restore)`. Only the last removal can be undone, and the bar is shared by all viewers.
  - When the queue is unsaved (no active playlist), "Guardar como playlist" sits in the action bar of `/playlist` (the unsaved queue). "Criar vazia" in `#nova` keeps the playing station, like any switch (`switch_queue()`).
- **Editing playlists**: the Playlists page links each playlist to its page, and its ▶ loads it (`switch_queue()`, the music goes on). On the playlist page, "Selecionar" (script only) puts `selecting` on `.main`: each card gets a `.tile-check` label covering it, with a checkbox that belongs to the `#editar` form through the `form` attribute (the card forms can't be nested in it), and tapping a card checks it instead of playing it. `#editar` is then a fixed bar above the player (`setSelecting()`/`updateSelection()` write "N estações escolhidas" and disable the buttons at 0; its ✕ leaves the mode and unchecks all). `/playlist_edit` copies, moves or removes the checked URLs (`acao`, `destino`) and redirects back, keeping `filtro`/`ordenar` from `next`, with `feito`/`n`/`destino`/`ja` for the notice (`EDIT_DONE` has singular and plural); `/rename_playlist` (modal `#renomear`) renames the file and the active name; deleting is the `#apagar` modal. All writes go through `append_to_playlist()` and `remove_from_playlist()`: for the active playlist they change the MPD queue and `sync_active()`, for any other only the file, so the music never changes. `para` (validated by `chosen_playlist()`: an existing playlist other than the active one, else empty) puts that playlist first in the + menu and in the stream-URL form's select, and is the default of "Juntar as desta página". The script reloads the page when `para` changes without a search. `/add_theme` into an existing playlist that isn't playing redirects to its page; `/delete_playlist` to `/playlists`.
- **Versions of the same station** (radio-browser lists the same station several times with different streams):
  - **Grouping:** `search_stations()` runs `clean_stations()` then `group_versions()`: one result per station, keyed by `group_key()` (`plain_text` name without quality marks, `QUALITY_WORDS_RE`, plus country, so "Radio 1" from two countries stay apart). The group keeps the first member's name and the best stream (`quality()`: bitrate × `CODEC_FACTOR`, unknown bitrate = 64, clicks break ties) and lists all streams in `variants` (`url`, `codec`, `bitrate`, `uuid`, `label`). `result_row()` shows a "N versões" `<details>` pill with ▶/+ for each (`station_buttons()` macro). `/add_theme` posts only the best of each group.
  - **Stored versions:** `~/.cache/vee-radio/versoes.json` maps every stream URL of a station to `{"t", "alts"}` (`load_versions()` is a shared copy reparsed on `file_sig()` change; `save_versions()` writes under `VERSIONS_LOCK` and drops entries for URLs in no playlist after a month). `remember_versions()` fills it from the in-memory search cache when a result is added or tried (`/add_stream`, `/add_theme`, `/ouvir`). For stations saved before, `station_versions()` (called by `player_context()`, so never blocking) starts `lookup_versions()` in the background: an API name search (quality marks stripped, accents kept) in the station's country, keeping the members of the same group; a stream not found there is stored alone. Refreshed weekly (`VERSIONS_MAX_AGE`).
  - **Player:** with more than one version, the detail line shows a `q-pill` ("128 kbps ▾") and `#tocar` lists them; `/versao` (POST, only URLs in the playing stream's `alts`) calls `replace_stream()`: `addid` the new URL at the same position, play it, `deleteid` the old one, and `sync_active(c, restore)` with the old name and logo (a station being tried stays a preview with the new URL).
  - **Automatic fallback:** done by the stream watchdog (see above), after the retries of a stream are used up: it replaces it with the best version not yet tried (`replace_stream()`, which returns the new song id and ignores a `playid` error so the watchdog can retry it).
- **Themes and countries** (`/tema?t=<tag>&pais=<code>`, GET, either or both): `THEMES` is a fixed list of radio-browser tags with Portuguese labels. The API's top tags are multilingual and mix genres with places ("méxico", "fm"), so they are not shown raw. `COUNTRIES` is likewise a fixed list of ISO codes with Portuguese names, because `/json/countries` only has English names ("The United States Of America"); the "Países" modal browses one country, and the label ("Rock (Portugal)" when both are set) names the new playlist. `search_filters()` reads `pais`, `lingua` (`LANGUAGES`, English names as in the API, matched as substrings so "portuguese" includes "brazilian portuguese"), `kbps` (`BITRATES`, sent as `bitrateMin`) and `ordem` (`ORDERS`: clickcount, votes, clicktrend, random, or name, A to Z) for both search and themes; unknown values fall back to the defaults. Results are paged with no overall limit: `pag` (`page_number()`, up to `MAX_PAGE`) becomes the API's `offset`, `PAGE_SIZE` (100) API entries per page, and `find_stations()` returns `(results, more)`, `more` when the API filled the page. After dropping HLS and duplicate URLs and grouping versions a page shows a bit fewer, and versions of one station may land on two pages; name order is re-sorted within the page. `page_url()` (template global) rebuilds the current URL with another `pag`, and the `pager()` macro shows Anteriores/Página N/Seguintes; the script shows skeleton rows in `.results` and scrolls to the top (same path would keep the scroll). Filter changes drop `pag`. The theme page's "Juntar" posts the stations of the current page ("Juntar as desta página" when there is more than one page); `BigFormRequest` lifts Werkzeug's 1000-field form limit. `find_stations()` serves search and themes. Results are kept in memory for `SEARCH_CACHE_SECONDS` (up to `SEARCH_CACHE_SIZE` pages), because adding a station from the results returns to the same `/search` or `/tema` page to show the ✓, which used to query the API again for every station added. API fields can be `null`: lists of stations go through `api_stations()` (a non-list answer becomes `ValueError`) and numbers through `to_int()`. `/add_stream` doesn't add a URL that is already in the queue. The `flag` template filter turns a country code into an emoji flag. The theme modal posts the stations it shows as parallel `url`/`name`/`logo` lists to `/add_theme`, so nothing is fetched again.
  - **Target** defaults to the active playlist (to a new playlist named after the theme when there is none). A new target becomes active and loaded. For an existing target, only missing URLs are appended. For the active playlist, the stations are also added to the queue.
- **Station logos**:
  - **Storage:** logo URLs live in the `#EXTINF` `tvg-logo="..."` attribute, so `read_m3u` returns `(url, name, logo)` triples and `write_m3u` writes them back.
  - **`station_info()`:** merges the playlists and `nomes.m3u`.
  - **Serving:** cards load `/logo/<sha1(stream url)[:16]>?n=<name>`. Logos bigger than `LOGO_SHRINK_ABOVE` are reduced to `LOGO_SIZE` px PNG with Pillow (`shrink_logo()`, when downloaded and, for older files, on first serve); without Pillow they stay as they came. That route serves `~/.cache/vee-radio/logos/<key>` and downloads it on first use, either from the known `tvg-logo` or via radio-browser's `byurl` lookup. Never look logos up by name: it returns stations from other countries. On failure it writes `<key>.falhou` to skip retries for a day (an hour for network errors and 5xx, by backdating its mtime) and returns an initials SVG. Downloads are written to a temp file and swapped in with `os.replace`, so a concurrent request never serves a half-written image.
  - **Safety:** the route only resolves keys of streams already in the playlists or queue, so the public link can't be used as an open fetch proxy. Logo URLs are still written by viewers (the `logo` field of `/add_stream`), so logos are downloaded only with `fetch_public()`: it refuses hosts that resolve to non-global addresses (private, loopback, link-local, CGNAT) and redirects to them (`PublicRedirects`). The check happens inside the connection (`public_connection()` as `_create_connection` of `PublicHTTP(S)Connection`), which then connects to the IP it checked, so a DNS answer can't change between check and connect; redirects go through the same connections, and leaving http(s) is refused. `image_type()` only takes as SVG a body that starts like an SVG, so an HTML page with an inline `<svg>` (a router's admin page) can't come back as an image. `LOGO_URL_RE` keeps logo URLs free of quotes, commas and parens, because they end up inside `#EXTINF` quotes and CSS `url()`. Search-result thumbnails load the favicon URL directly (`<img class="thumb" loading="lazy">`), followed by a hidden `.thumb.empty` radio icon; the script (`checkThumb()`, from `markLoaded`/`markLoadedImages`) swaps a thumbnail that failed or has `naturalWidth` ≤ 2 (empty placeholder images) for that icon. Images not yet loaded (`!complete`, lazy) are left alone.
- **Station names** come from `#EXTINF` lines in the `.m3u` files (all files in `PLAYLIST_DIR` plus `~/.config/mpd/nomes.m3u`, where names typed in "add stream" are appended, only when they differ from the last entry for that URL), never from MPD tags. `station_index()` caches the parsed files and the per-playlist counts, and only rereads them when a file's inode, mtime or size changes: `/estado` (every 5s per viewer), every page and every logo miss need the names. `station_info()` returns that shared dict, so callers must not mutate it. MPD exposes `#EXTINF` as the `name` tag, but once a stream plays MPD replaces that queue entry's tags with the stream's ICY tags for good. MPD's `save` writes bare URLs, so the app writes the `.m3u` files itself (`queue_entries()`) to keep names. `PLAYLIST_DIR` in `radio_web.py` must match `playlist_directory` in `mpd.conf`.
- **Radio search** (`/search`, GET) queries the radio-browser.info API with stdlib `urllib`, so there is no extra dependency. Results are posted to `/add_stream` with a `next` field so the user lands back on the results. HLS (`.m3u8`) results are filtered out: the Windows MPD build cannot play them, and Termux support is unconfirmed. Stream URLs must be `http(s)://` (`safe_url()`, used by `/add_stream`, `/add_theme` and search results): MPD would otherwise accept a path in the music folder or other input plugins (`smb://`, `nfs://`). Network errors are caught inside the route, because the app-wide `OSError` handler reports them as "MPD indisponível".
- **start.sh** kills any old instances and runs `mpd`. MPD restores the queue itself. If the queue comes back empty, start.sh reloads the playlist named in `playlist-ativa.txt`. There is no bundled starter playlist: a fresh install starts empty and the user builds playlists from search or themes. Everything else runs in the background with `nohup`, so Termux can be closed afterwards:
  - the web app, logging to `~/web.log`;
  - `cloudflared`, logging to `~/tunnel.log`, unless the tunnel is off.

  **No tunnel:** `TUNNEL_ENABLED=0` in `.env` (`tunnel_enabled()`; missing means on, for older installs) skips cloudflared, ntfy and the share page: start.sh waits for the web app and opens `http://localhost:8080` with `termux-open-url`. The remote then works on the phone and on the LAN only.

  The script waits up to 60s for the trycloudflare URL to appear in the log and writes it to `~/tunnel-url.txt`. The page never shows the link (it is the only access key and reaches the owner by ntfy or the local share page); `radio_web.py` reads the file only to accept the tunnel as `Origin` (`tunnel_host()`).
  - **ntfy:** if `.env` in the repo dir (gitignored; `install.sh` copies `.env.example` there when missing) sets `NTFY_TOPIC_URL`, `send_ntfy` POSTs the link with curl. The value is a bare topic name (sent to `ntfy.sh`) or a full server URL; optional `NTFY_TOKEN` adds a Bearer header. The token goes to curl through `-K <(...)` in `ntfy_curl()`, never on the command line, and the process substitution must stay inside the curl command itself (bash closes it if stored in a variable). On `ntfy.sh` without a token, topics shorter than 16 characters are refused, because whoever knows the topic gets the link. Headers stay ASCII, and the UTF-8 body goes through stdin, because ntfy turns a non-UTF-8 body into an attachment. `env_value` parses `KEY=value` with sed instead of sourcing the file. When the send succeeds, the share page is skipped; when there is no topic or the send fails, the share page below opens as before.
  - **Share page:** start.sh fills `__URL__` in [link.html](link.html), serves the result with `python -m http.server 8081` bound to `127.0.0.1` only (from `~/.vee-radio-link/`), and opens it with `termux-open-url`. That page has copy and share buttons. The URL changes on every start. **stop.sh** must kill everything start.sh launches.
- **Settings** (`⚙` in Início's header (the dashboard), `#config` modal in `layout.html`, POST `/config`): edits `TUNNEL_ENABLED`, `NTFY_TOPIC_URL` and `NTFY_TOKEN` in `.env`. "Guardar" applies on the next start.sh; "Guardar e aplicar agora" (`aplicar`) calls `restart_all()`, which reruns start.sh in its own session (`start_new_session`, after `sleep 2` so the response gets out) because start.sh kills this server, with `VEE_RADIO_NO_OPEN=1` so it doesn't open another browser tab. That route answers 202 with a `Refresh` header; the script reads it and returns to `/` after that time.
  - **Who can open them:** `can_configure()` = `is_local()` plus the settings key cookie. Anyone with the tunnel link could otherwise point ntfy at their own topic and get every future link, and any other Android app can reach `localhost:8080`.
    - `is_local()`: loopback `remote_addr`, a `localhost`/`127.0.0.1` Host and none of `Cf-Connecting-IP`, `Cf-Ray`, `X-Forwarded-For` (tunnel requests also come from 127.0.0.1, but Cloudflare always adds `Cf-Connecting-IP`).
    - **Key:** `~/.config/vee-radio/chave` (mode 600, created by `ensure_config_key()` when the app starts) can only be read by Termux. `/entrar?chave=...` (local only, `hmac.compare_digest`) stores it in an HttpOnly, SameSite=Lax cookie. Not Strict: the link arrives from another app (`termux-open-url`), which the browser treats as a cross-site navigation, so a Strict cookie wasn't sent on the redirect that follows and the page opened without the settings. start.sh opens that link when the tunnel is off; `~/config.sh` opens it with `ir=config` at any time.
  - **`.env` handling:** the token is never rendered (an empty field keeps it, a checkbox clears it). `read_env()` parses like start.sh's `env_value` (last occurrence wins, outer quotes stripped); `write_env()` keeps comments and other keys, starts from `.env.example` when there is no `.env`, writes atomically with mode 600, and only writes validated values (no spaces or quotes), so start.sh's sed parsing stays safe. `weak_ntfy_topic()` applies the same 16-character rule as start.sh.
- **Updating** ([update.sh](update.sh), linked as `~/update.sh`): `git fetch`, then only a fast-forward to the upstream (`merge --ff-only`); local commits or edits that block it leave the current version. It runs `install.sh` only when `install.sh` changed between the old and new `HEAD`, because that upgrades the packages. Modes: no argument updates and `exec`s start.sh when there was something new; `--check` only reports (exit 0 = new commits, printing `instalar` when `install.sh` changed; 3 = up to date; 1 = failed, with a Portuguese reason as the last stdout line); `--boot` waits up to 30s for github.com and updates without restarting. The settings modal has "Procurar atualizações" (POST `/atualizar`, `can_configure()` only): it runs `--check` synchronously (so nothing stops when there is nothing new; `/?atualizacao=nada#config` shows "Já tens a versão mais recente"), then `restart_all(UPDATE_SCRIPT)` and a 202 page with `Refresh` (240s when `install.sh` runs, else 20s). `app_version()` (short hash and commit date, read once per process) is shown in the modal.
- **Termux:Boot**: `install.sh` writes `~/.termux/boot/vee-radio`. It runs `~/update.sh --boot` and then `~/start.sh --boot`, logging to `~/boot.log`. With `--boot`, start.sh waits up to 2 minutes for internet right before starting cloudflared, and only when the tunnel is on, so MPD and the local remote come up at once. Boot scripts from older installs wait themselves and call start.sh without `--boot`, which also works.
- **install.sh** is idempotent and is meant to be run as `curl | bash`. All logic sits inside `main()` so bash reads the whole script before running any of it. It links `~/start.sh`, `~/stop.sh`, `~/config.sh` and `~/update.sh` to the repo, and symlinks `~/.config/mpd/mpd.conf` to the repo copy, so edits to `mpd.conf` apply after `git pull`. `REPO_URL` points to the public repo `github.com/vitor-gsousa/vee-radio`. It can be overridden with `VEE_RADIO_REPO`.

## Running / testing on the device

```bash
~/start.sh                              # start MPD + web (port 8080) + tunnel
~/stop.sh                               # stop everything, release the wake lock
~/config.sh                             # open the settings (⚙) in the phone's browser
~/update.sh                             # update from GitHub and restart if there is something new
cd ~/vee-radio && git pull && bash install.sh && ~/start.sh   # full update (install.sh re-applies config such as the boot script)
mpc status / mpc playlist               # inspect MPD directly
```

To check web UI changes locally without the phone, you need a running MPD. On Windows the official build works (`https://www.musicpd.org/download/win32/<versão>/mpd.exe`). It needs a `libz.dll` next to it, and a copy of Git's `zlib1.dll` (in `C:\Program Files\Git\mingw64\bin` or `ucrt64\bin`) renamed to `libz.dll` works. Use `audio_output { type "null" }`. Real radio streams play fine through it, so ICY tag behaviour can be observed. The Python dependencies are `flask` and `python-mpd2`, plus optional Pillow (`python-pillow` in Termux, installed by install.sh) for shrinking logos.

## Constraints

- Shell scripts use the Termux shebang `#!/data/data/com.termux/files/usr/bin/bash` and must keep LF line endings (enforced by [.gitattributes](.gitattributes)). Termux rejects CRLF.
- All user-facing text (UI, script output, README, comments) is in European Portuguese. Keep it that way.
- The web remote has no authentication, so anyone with the tunnel link can control it. Beyond that, `check_origin()` (`before_request`) blocks other sites:
  - **Host:** only `localhost`, IP literals (LAN access as `http://<IP>:8080`) and `*.trycloudflare.com`, against DNS rebinding. A `.local` name doesn't work.
  - **POST (CSRF):** `Sec-Fetch-Site` must be `same-origin` or `none`; browsers that don't send it must send an `Origin` equal to the `Host` or to the tunnel (cloudflared may rewrite `Host`). No headers at all (curl) is allowed, since that isn't a browser being tricked.
  - **Sizes:** `MAX_CONTENT_LENGTH` is 2 MB, stream URLs up to `MAX_URL`, names cut to `MAX_NAME` (`clean_name()`), playlist names up to `MAX_PLAYLIST_BYTES` UTF-8 bytes (they are file names).
