# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A radio jukebox for an old Android phone running Termux. MPD plays the radio streams, a single-file Flask app ([radio_web.py](radio_web.py)) is the web remote, and a Cloudflare quick tunnel exposes that remote publicly. Development happens on Windows, but everything runs only on the phone under Termux. There is no build step, test suite or linter.

## Runtime architecture

- **MPD** listens on `127.0.0.1:6600` only (the app and `mpc` connect to localhost; open to the LAN, anyone on the same Wi-Fi had the full MPD protocol, `kill` included) and outputs audio through Android OpenSLES (`type "sles"`, software mixer, see [mpd.conf](mpd.conf)). Its paths use Termux conventions: playlists in `~/.config/mpd/playlists`, music in `~/storage/shared/Music`. Queue and state survive restarts through `state_file`.
- **radio_web.py** is stateless. Every route opens a fresh `MPDClient` connection to `localhost:6600`, runs one or two MPD commands, disconnects, then redirects to `/` (POST-redirect-GET). The UI is Jinja templates in [templates/](templates/), rendered with `render_template`: `base.html` holds all the CSS, and `index.html` and `error.html` extend it. The player is a fixed footer bar in `player.html`, included by `index.html` and also rendered by `/estado` (Spotify style: station on the left, previous/play-stop/next in the centre, volume on the right). Below 900px the volume drops to a second row of the bar, and the body has bottom padding so the bar never covers content. `/previous` and `/next` wrap around the queue. A sticky top bar (`.topbar`) holds the "Juntar rádio", "Temas" and "Países" buttons.
- **Station list filter and sort** (GET `/?filtro=...&ordenar=clickcount|votes|name|-name`): `render_index` sorts the tiles and renders the ones that don't match with `hidden`, so the script can filter while typing without a request. `plain_text()` (server) and `plain()` (script) must normalise the same way (NFKD, drop `\p{M}`, lowercase), or the page and live filter show different stations. This only changes the view: MPD positions (`data-pos`), the saved playlist and previous/next keep the playlist order. The order dropdown reuses the `order_select` macro of the radio-browser filters, with `LIST_ORDERS`.
- **Station popularity and details** (`station_stats()`): sorting by clickcount (clicks in the last 24h), votes or clicktrend (change in clicks from the previous day), and the footer details, need radio-browser data for stations already in the queue. It is cached in `~/.cache/vee-radio/stats.json` for a day. Each entry maps a stream URL to `uuid`, `clickcount`, `votes`, `clicktrend`, `countrycode`, `tags` (up to 3), `homepage`, `codec`, `bitrate`, `voted_at` and `t`. Bump `STATS_VERSION` when fields are added, so older entries count as stale. All writes go through `merge_stats()`, which rereads the file under `STATS_LOCK` and keeps `voted_at`.
  - **Known `uuid`:** stations with a known `uuid` are refreshed in one `byuuid` request (100 per call). Search and theme forms post `uuid` next to `url`, and `remember_uuids()` stores it when a station is added.
  - **Unknown `uuid`:** the rest are looked up with `byurl`, 8 in parallel, keeping the most clicked duplicate.
  - **Network failure:** a failed lookup keeps the old numbers and retries after an hour. After the first network error (`api_down`) the remaining lookups are skipped, so sorting a big list with the API down doesn't wait for every timeout.
- **Footer details** (`station_details()`): the player shows the flag, a detail line (MPD's live `bitrate`, falling back to the API's, plus the tags; phones show only the bitrate), a site link and a vote button.
  - **Never blocks:** `/estado` is polled every 5s, so `station_details()` only reads the cache. When the entry is missing or stale, it starts a background thread (deduplicated through `_refreshing`), and the footer fills in on a later poll because its `data-sig` includes the details.
  - **Votes:** `/vote` (POST) votes for the playing station through `/json/vote/<uuid>`. radio-browser allows one vote per IP per station every 10 minutes (`VOTE_COOLDOWN`), and all viewers share the phone's IP. The route returns `estado(notice)`, and the script shows `notice` as a toast (green when `ok`). Tile forms carry a `next` field and their routes return via `back()`, so playing or removing a station keeps the filter. Their `next` is `list_url` (`/` plus only `filtro` and `ordenar`), never `/search` or `/tema`, which would query the API again. The script rebuilds `next` the same way (`listUrl()`) before sending, because the live filter only changes the URL, and when the search or theme modal closes it replaces `/search` or `/tema` in the URL with `listUrl()`, so later soft reloads don't hit the API. New features follow the same pattern: a POST route plus a `<form>` in the template. Forms live in CSS-only modals opened with `:target` (a link to `#juntar` shows `<div class="modal" id="juntar">`, a link to `#fechar` hides it), so a redirect to `/...#juntar` reopens a modal after a POST.
- **JavaScript is progressive enhancement** ([static/app.js](static/app.js)): everything must keep working without it, so never add a feature that only works through the script. It sends every form with `fetch` and the `X-Requested-With: fetch` header:
  - For those requests an `after_request` hook turns redirects into `204` with an `X-Location` header, because `fetch` follows redirects itself and drops the `#modal` fragment. The script then GETs that location and swaps `document.body`, keeping the page and open-modal scroll.
  - The player routes (`play_id`, `play`, `stop`, `previous`, `next`, `volup`, `voldown`) return `done()`, which gives the script the `/estado` JSON instead of a redirect.
  - Modals also open with a `.open` class kept in sync with `location.hash`, because `:target` does not follow `pushState` or swapped elements.
  - **Skeletons:** a `js` class on `<html>` (set inline in `base.html`) makes logos and thumbnails shimmer until their `load`/`error` event adds `.loaded`. A GET form replaces the `.results` container of its modal with skeleton rows, or adds `.is-loading` to `.stations` for the list tools. A theme or country chip opens a temporary modal with skeleton rows, because the `#tema` modal does not exist yet. If the request fails, all of this is undone.
  - **Live search:** typing in the search box submits after 700ms (3+ characters). Changing a filter submits the search (when it has text) or the theme `.refine` form, whose button is then hidden. `loadSeq` drops responses older than the latest page request, and the focused text field (value and caret) survives the body swap.
  - Every 5s the script polls `/estado` and replaces the footer when its `data-sig` changes, moves the `.current` tile and sets the tab title. `stateSeq` drops a poll response that was requested before a form was sent, so an old state can't undo a button press in the footer. When the queue signature (`queue_sig()`, a hash of the MPD song ids, on `#estacoes` as `data-queue`) or the error state differs from the page, it reloads the page softly, but never while a modal is open. MPD's own queue version (`status.playlist`) is not used, because it also changes when the playing stream's ICY tags change, which reloaded the page on every song.
- **Active playlist**: the MPD queue is always the playlist named in `~/.config/mpd/playlist-ativa.txt`. `/add_stream` and `/remove` call `sync_active()`, which rewrites that `.m3u` from the queue, so there is no save button. Every route that reads the queue and rewrites `.m3u` files holds `QUEUE_LOCK`, and `write_m3u` writes a `.tmp` and swaps it in with `os.replace`, so concurrent viewers never see or save a half-written playlist. Tiles play and remove by MPD song `id` (`/play_id/<id>`, `/remove/<id>` with `deleteid`), never by position, because the queue may have changed on another device since the page was rendered. Loading a playlist clears the active file before `clear` + `load` and sets it again afterwards, so a failed `load` can't make the next sync overwrite the previous playlist with an empty queue. URLs and playlist names with control characters are rejected (`safe_url`, `playlist_path`), because python-mpd2 doesn't escape newlines and they would inject MPD commands. Loading or creating a playlist makes it active, and deleting the active one clears the file, which leaves the queue unsaved. There is deliberately no "clear queue" action, because with sync it would wipe the playlist.
- **Themes and countries** (`/tema?t=<tag>&pais=<code>`, GET, either or both): `THEMES` is a fixed list of radio-browser tags with Portuguese labels. The API's top tags are multilingual and mix genres with places ("méxico", "fm"), so they are not shown raw. `COUNTRIES` is likewise a fixed list of ISO codes with Portuguese names, because `/json/countries` only has English names ("The United States Of America"); the "Países" modal browses one country, and the label ("Rock (Portugal)" when both are set) names the new playlist. `search_filters()` reads `pais`, `lingua` (`LANGUAGES`, English names as in the API, matched as substrings so "portuguese" includes "brazilian portuguese"), `kbps` (`BITRATES`, sent as `bitrateMin`) and `ordem` (`ORDERS`: clickcount, votes, clicktrend, random, or name, which means "all, A to Z" and raises the limit to `ALL_LIMIT`; `BigFormRequest` lifts Werkzeug's 1000-field form limit so `/add_theme` accepts that many) for both search and themes; unknown values fall back to the defaults. `find_stations()` serves both: it fetches with those filters, drops HLS and duplicate URLs, and trims to the limit. API fields can be `null`: lists of stations go through `api_stations()` (a non-list answer becomes `ValueError`) and numbers through `to_int()`. `/add_stream` doesn't add a URL that is already in the queue. The `flag` template filter turns a country code into an emoji flag. The theme modal posts the stations it shows as parallel `url`/`name`/`logo` lists to `/add_theme`, so nothing is fetched again.
  - **Target** defaults to a new playlist named after the theme. A new target becomes active and loaded. For an existing target, only missing URLs are appended. For the active playlist, the stations are also added to the queue.
- **Station logos**:
  - **Storage:** logo URLs live in the `#EXTINF` `tvg-logo="..."` attribute, so `read_m3u` returns `(url, name, logo)` triples and `write_m3u` writes them back.
  - **`station_info()`:** merges the playlists and `nomes.m3u`.
  - **Serving:** cards load `/logo/<sha1(stream url)[:16]>?n=<name>`. That route serves `~/.cache/vee-radio/logos/<key>` and downloads it on first use, either from the known `tvg-logo` or via radio-browser's `byurl` lookup. Never look logos up by name: it returns stations from other countries. On failure it writes `<key>.falhou` to skip retries for a day (an hour for network errors and 5xx, by backdating its mtime) and returns an initials SVG. Downloads are written to a temp file and swapped in with `os.replace`, so a concurrent request never serves a half-written image.
  - **Safety:** the route only resolves keys of streams already in the playlists or queue, so the public link can't be used as an open fetch proxy. Logo URLs are still written by viewers (the `logo` field of `/add_stream`), so logos are downloaded only with `fetch_public()`: it refuses hosts that resolve to non-global addresses (private, loopback, link-local, CGNAT) and redirects to them (`PublicRedirects`). The check happens inside the connection (`public_connection()` as `_create_connection` of `PublicHTTP(S)Connection`), which then connects to the IP it checked, so a DNS answer can't change between check and connect; redirects go through the same connections, and leaving http(s) is refused. `image_type()` only takes as SVG a body that starts like an SVG, so an HTML page with an inline `<svg>` (a router's admin page) can't come back as an image. `LOGO_URL_RE` keeps logo URLs free of quotes, commas and parens, because they end up inside `#EXTINF` quotes and CSS `url()`. Search-result thumbnails use the favicon URL directly as a CSS background.
- **Station names** come from `#EXTINF` lines in the `.m3u` files (all files in `PLAYLIST_DIR` plus `~/.config/mpd/nomes.m3u`, where names typed in "add stream" are appended, only when they differ from the last entry for that URL), never from MPD tags. MPD exposes `#EXTINF` as the `name` tag, but once a stream plays MPD replaces that queue entry's tags with the stream's ICY tags for good. MPD's `save` writes bare URLs, so the app writes the `.m3u` files itself (`queue_entries()`) to keep names. `PLAYLIST_DIR` in `radio_web.py` must match `playlist_directory` in `mpd.conf`.
- **Radio search** (`/search`, GET) queries the radio-browser.info API with stdlib `urllib`, so there is no extra dependency. Results are posted to `/add_stream` with a `next` field so the user lands back on the results. HLS (`.m3u8`) results are filtered out: the Windows MPD build cannot play them, and Termux support is unconfirmed. Stream URLs must be `http(s)://` (`safe_url()`, used by `/add_stream`, `/add_theme` and search results): MPD would otherwise accept a path in the music folder or other input plugins (`smb://`, `nfs://`). Network errors are caught inside the route, because the app-wide `OSError` handler reports them as "MPD indisponível".
- **start.sh** kills any old instances and runs `mpd`. MPD restores the queue itself. If the queue comes back empty, start.sh reloads the playlist named in `playlist-ativa.txt`. There is no bundled starter playlist: a fresh install starts empty and the user builds playlists from search or themes. Everything else runs in the background with `nohup`, so Termux can be closed afterwards:
  - the web app, logging to `~/web.log`;
  - `cloudflared`, logging to `~/tunnel.log`.

  The script waits up to 60s for the trycloudflare URL to appear in the log and writes it to `~/tunnel-url.txt`. The page never shows the link (it is the only access key and reaches the owner by ntfy or the local share page); `radio_web.py` reads the file only to accept the tunnel as `Origin` (`tunnel_host()`).
  - **ntfy:** if `.env` in the repo dir (gitignored; `install.sh` copies `.env.example` there when missing) sets `NTFY_TOPIC_URL`, `send_ntfy` POSTs the link with curl. The value is a bare topic name (sent to `ntfy.sh`) or a full server URL; optional `NTFY_TOKEN` adds a Bearer header. The token goes to curl through `-K <(...)` in `ntfy_curl()`, never on the command line, and the process substitution must stay inside the curl command itself (bash closes it if stored in a variable). On `ntfy.sh` without a token, topics shorter than 16 characters are refused, because whoever knows the topic gets the link. Headers stay ASCII, and the UTF-8 body goes through stdin, because ntfy turns a non-UTF-8 body into an attachment. `env_value` parses `KEY=value` with sed instead of sourcing the file. When the send succeeds, the share page is skipped; when there is no topic or the send fails, the share page below opens as before.
  - **Share page:** start.sh fills `__URL__` in [link.html](link.html), serves the result with `python -m http.server 8081` bound to `127.0.0.1` only (from `~/.vee-radio-link/`), and opens it with `termux-open-url`. That page has copy and share buttons. The URL changes on every start. **stop.sh** must kill everything start.sh launches.
- **Termux:Boot**: `install.sh` writes `~/.termux/boot/vee-radio`. It waits up to 2 minutes for internet, then runs `~/start.sh`, logging to `~/boot.log`.
- **install.sh** is idempotent and is meant to be run as `curl | bash`. All logic sits inside `main()` so bash reads the whole script before running any of it. It symlinks `~/.config/mpd/mpd.conf` to the repo copy, so edits to `mpd.conf` apply after `git pull`. `REPO_URL` points to the public repo `github.com/vitor-gsousa/vee-radio`. It can be overridden with `VEE_RADIO_REPO`.

## Running / testing on the device

```bash
~/start.sh                              # start MPD + web (port 8080) + tunnel
~/stop.sh                               # stop everything, release the wake lock
cd ~/vee-radio && git pull && bash install.sh && ~/start.sh   # update (install.sh re-applies config such as the boot script)
mpc status / mpc playlist               # inspect MPD directly
```

To check web UI changes locally without the phone, you need a running MPD. On Windows the official build works (`https://www.musicpd.org/download/win32/<versão>/mpd.exe`). It needs a `libz.dll` next to it, and a copy of Git's `zlib1.dll` (in `C:\Program Files\Git\mingw64\bin` or `ucrt64\bin`) renamed to `libz.dll` works. Use `audio_output { type "null" }`. Real radio streams play fine through it, so ICY tag behaviour can be observed. The Python dependencies are `flask` and `python-mpd2`.

## Constraints

- Shell scripts use the Termux shebang `#!/data/data/com.termux/files/usr/bin/bash` and must keep LF line endings (enforced by [.gitattributes](.gitattributes)). Termux rejects CRLF.
- All user-facing text (UI, script output, README, comments) is in European Portuguese. Keep it that way.
- The web remote has no authentication, so anyone with the tunnel link can control it. Beyond that, `check_origin()` (`before_request`) blocks other sites:
  - **Host:** only `localhost`, IP literals (LAN access as `http://<IP>:8080`) and `*.trycloudflare.com`, against DNS rebinding. A `.local` name doesn't work.
  - **POST (CSRF):** `Sec-Fetch-Site` must be `same-origin` or `none`; browsers that don't send it must send an `Origin` equal to the `Host` or to the tunnel (cloudflared may rewrite `Host`). No headers at all (curl) is allowed, since that isn't a browser being tricked.
  - **Sizes:** `MAX_CONTENT_LENGTH` is 2 MB, stream URLs up to `MAX_URL`, names cut to `MAX_NAME` (`clean_name()`), playlist names up to `MAX_PLAYLIST_BYTES` UTF-8 bytes (they are file names).
